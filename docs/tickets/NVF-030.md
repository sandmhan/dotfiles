# NVF-030: Extract NVF configuration as reusable flake input

## Summary

Create a standalone, reusable NVF flake input from this repository's NVF Home Manager configuration.

## Purpose

Allow other flakes and repositories to integrate the curated NVF IDE setup without copying this dotfiles repository or importing its connected Home Manager modules.

## Context

The approved NVF enterprise polyglot IDE work has produced a cohesive module set under `home/modules/nvf/`. The next step is to make that editor configuration portable by extracting or publishing it as its own flake input with a narrow dependency boundary. The extracted flake must keep host-, user-, secret-, and dotfiles-specific modules out of the reusable interface while preserving the existing local integration path.

## Acceptance criteria

- [ ] A reusable NVF flake is created or extracted with a minimal `flake.nix` that exposes the NVF Home Manager module and required inputs without importing unrelated dotfiles modules.
- [ ] This dotfiles repository consumes the reusable NVF module through the new flake input or an equivalent local path during development, with no duplicated NVF configuration.
- [ ] Consumer-facing options, required inputs, and integration examples are documented for downstream flakes.
- [ ] Host-, user-, machine-, and secret-specific settings remain outside the reusable NVF flake boundary.
- [ ] Validation evidence includes evaluation of the extracted flake plus the affected Home Manager profile dry-run or equivalent build check.
- [ ] `README.md` and `docs/neovim-ide.md` remain synchronized with the resulting NVF import path and consumer workflow.
