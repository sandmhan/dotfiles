# NVF-032: Restore NVF CodeCompanion Codex ACP workflow

## Summary

Restore CodeCompanion.nvim as the only NVF in-editor AI integration, using Codex ACP through `codex-acp` with ChatGPT authentication for chat. Retire the stale Avante.nvim and `NvfAi*` bridge wiring from active NVF imports while keeping standalone Claude, Codex, and Pi Home Manager tooling intact.

## Purpose

Keep Neovim AI on the NVF-supported CodeCompanion chat path and avoid committing API-key, OpenAI-compatible endpoint, Avante, or custom `NvfAi*` bridge configuration in the active editor profile.

## Context

NVF-031 established a mature CodeCompanion workflow. A follow-up Avante direction was later reversed: the current implementation uses CodeCompanion with the upstream Codex ACP adapter and ChatGPT auth (`auth_method = "chatgpt"`). The previous Avante evidence remains historical only; it is not the active Neovim AI design.

## Acceptance criteria

- [x] `home/modules/nvf/default.nix` imports `home/modules/nvf/ai-codecompanion.nix` after workspace hardening and before completion.
- [x] `home/modules/nvf/ai-codecompanion.nix` enables `vim.assistant.codecompanion-nvim` behind the high-level `programs.sandvim.enable` option.
- [x] The CodeCompanion feature installs `pkgs.codex-acp`.
- [x] CodeCompanion chat uses the `codex` ACP adapter with `auth_method = "chatgpt"` and command `codex-acp`.
- [x] Unsupported CodeCompanion command/inline/action-palette interactions are not wired to the Codex ACP adapter and are not exposed through NVF keymaps.
- [x] No Neovim AI API key, `openai_compatible`, Avante, or `NvfAi*` bridge wiring is active in NVF.
- [x] The portable Sandvim API is a single high-level `programs.sandvim.enable` option; CodeCompanion/Codex ACP is included behavior.
- [x] Affected Home Manager profiles enable `myHome.features.enableNixvim`, which the flake-local adapter maps to `programs.sandvim.enable`.
- [x] `README.md`, `docs/neovim-ide.md`, Phase 5/7 validation scripts, and evidence documentation describe the CodeCompanion-only Codex ACP workflow and the standalone CLI boundary for Claude, Codex, and Pi.
- [x] Validation evidence covers phase scripts, whitespace checks, and runtime command smoke checks when the build-local NVF package can be built.

## Limitations

- CodeCompanion does not inherit the retired bridge's redaction, sensitive-path blocking, confirmation summary, or full-buffer-selection guardrails.
- ChatGPT/Codex authentication is performed outside Nix; no credentials are committed.
- Runtime checks use a build-local NVF package when possible and do not activate Home Manager profiles.
