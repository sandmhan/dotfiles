# NVF-033: Add NVF Phase 8 polyglot workflow support

## Summary

Add portable Sandvim/NVF support for Rust, Go, Lua, SQL, Dart/Flutter, Obsidian-style Markdown notes, professional workflow plugins, and Vim-aware tmux pane navigation.

## Purpose

Move the approved enterprise polyglot IDE roadmap beyond Python, web, infrastructure, AI, and DAP by adding common systems/data/mobile languages and day-to-day navigation/review tooling while preserving the high-level `programs.sandvim.enable` gate.

## Acceptance criteria

- [x] `home/modules/nvf/languages-systems.nix` enables Rust, Go, and Lua LSP, Treesitter, formatting, and linting/tool integrations behind `programs.sandvim.enable`.
- [x] `home/modules/nvf/languages-data-mobile.nix` enables SQL and Dart/Flutter support behind `programs.sandvim.enable`, with `flutter-tools.flutterPackage = null` so Flutter is resolved from PATH/devshell. `enableNoResolvePatch` remains disabled because NVF's current patch fails against the pinned flutter-tools.nvim source.
- [x] Markdown uses markdown-oxide and mdformat rather than Marksman/prettierd as the active owner.
- [x] Obsidian note navigation is enabled with a dynamic current-workspace root and modern `:Obsidian <subcommand>` mappings under `<leader>n`.
- [x] Workflow tooling enables Trouble, GrugFar, Diffview, fastaction, nvim-lightbulb, mini.align/splitjoin/move, and vim-sleuth with non-conflicting keymaps.
- [x] Smart-splits is enabled in NVF and tmux loads the packaged `smart-splits.tmux` script instead of unconditional `C-h/j/k/l select-pane` bindings.
- [x] Workspace hardening recognizes Rust, Go, Lua, SQL, and Dart/Flutter root markers.
- [x] `README.md`, `docs/neovim-ide.md`, the ticket index, and validation evidence are synchronized with the imported modules and implemented behavior.
- [x] `scripts/check-nvf-phase8.sh` verifies repeatable option, import, docs, and tmux integration assertions.

## Limitations

- Rust, Go, and Dart DAP are intentionally disabled until project-specific debug profiles are designed.
- Flutter SDK installation is intentionally project/devshell-owned; the shared editor wrapper does not bundle `pkgs.flutter`. Use a non-Nix Flutter SDK on PATH until NVF's no-resolve patch applies cleanly to the pinned flutter-tools.nvim source.
- SQL dialect defaults to `ansi`; project repositories should own dialect-specific SQLFluff configuration.
- Runtime command checks use a build-local NVF package when practical and do not activate Home Manager profiles.
